## سبب الإصلاح ومسارات الرموز

نجح الدخول في0.3.1، لكن إنشاء الغرفة فشل قبل وصول أي POST: كان اسم الغرفة عشرة أرقام صحيحة حتى save_ready، ثم أضاف ضغط الحفظ حرفًا؛ بقيت النافذة ولوحة المفاتيح ظاهرتين، وعدّادات HTTP والخادم وDB كلها صفر. كذلك أثبتت المراجعة الفعلية لصورة الدردشة اختفاء المحرر خلف IME رغم نجاح الحارس القديم.

جرى فحص هذه المسارات فقط، دون إعادة قراءة المستودع:
- `NativeApp / VisualEntry → SafeAreaView → RoomScreen / FormScreen`.
- `RoomEditor → Sheet → FormScreen → footer`.
- `create_native_host_room → tap_room_save → native_ime_geometry.observe`.
- إغلاق المضيف: `runExit → executeRoomExit → voice.leave` محليًا، ثم `rooms.end/endRoom → POST close → authoritative inactive/empty snapshot → auth.signOut`. مغادرة المستمع أو «مغادرة دون إنهاء» لا تغلق البث.

الإصلاح الحالي يضع KeyboardViewport واحدًا عند جذر كل نافذة قبل safe areas؛ Modal يملك واحدًا مستقلًا. أزيل تجنّب لوحة المفاتيح المتداخل من RoomScreen وعُطل داخل FormScreen عندما يملكه الجذر. لم تتغير المصادقة أو واجهات الخادم أو DB أو SDK الصوت.

حارس QA يقارن كامل حدود زر الحفظ وحقل الدردشة والإرسال بحدود IME الظاهرة، بوحدات physical px. يمنع الضغط/التصوير إذا وجد تداخل أو تعذر تحديد الهندسة، ويحتفظ بالأرقام والحالات الآمنة فقط. لا BACK داخل نافذة الإنشاء ولا إعادة POST تلقائية. الصور الأصلية تبقى في artifacts؛ خُفضت الصور المضمنة في السجلات إلى512KiB بعد فشل جلب سجل كبير بـTransport closed.
