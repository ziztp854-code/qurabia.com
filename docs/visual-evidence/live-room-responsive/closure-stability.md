# استقرار النقل تحت دورات مغادرة وعودة متتابعة

المراجع المستقل: `close_stability`. التاريخ: 21 أكتوبر 2026 UTC.
المرجع: [تقرير الاعتماد السابق](approval-final.md).

**نجحت الجولة الجديدة مرة واحدة:** 12 دورة مغادرة وعودة، وثلاث عمليات قطع فعلي
لـWebSocket الإشارة ثم تعافي SDK، بعمليتي native مستقلتين وSFU معزول مصحح.
استغرق التنفيذ 48.84s، برمز خروج 0؛ لم تُعد جولة HTTP السابقة ذات الـ80 عملية.

هذا نقل WebRTC فعلي مع PCM مولد 440/660Hz؛ لا ميكروفونات أو سماعات أو هاتف فعلي،
ولا browser AudioSession أو تسجيل دخول التطبيق أو بوابة admission الإنتاجية.
لا يثبت الحمل المحدود سعة إنتاج أو غياب كل تسرب، ولا تُعد الـ12 دورة اختبارات
وحدة إضافية إلى المجموعة الشاملة.

## التصميم وما اختُبر فعليًا

- عميلان مستقلان PID 67741 و67752؛ يبقى B متصلًا بينما يغادر A ويعود 12 مرة.
- كل دورة تؤكد العضوية 2→1→2، وفك PCM في الاتجاهين بعد العودة. استُخدم FFT
  Hann مع ±25Hz وRMS>300 و15 إطارًا على الأقل وتركيز طاقة ≥80% في الحزمة المتوقعة.
  البصمات في JSON تثبت تنفيذ الجولة على oracle وإعداد العزل المصححين.
- توقف المصدر المولد قبل disconnect في كل مغادرة. لا طاقة PCM من مصدر A
  الوحيد لدى B بعد سماح التصريف المعلن 250ms. لا نستنتج صمتًا سمعيًا على جهاز فعلي.
- عند الدورات 4 و8 و12 قُطع socket إشارة قائم فعليًا، ورُصد حدث `reconnected`
  جديد مع PCM سليم. لم يُقطع مسار ICE أو شبكة الجهاز أو TURN؛ قد تستمر الوسائط
  أثناء انقطاع الإشارة، ولذلك ليست هذه شهادة تعافي من انقطاع وسائط كامل.
- بعد كل مغادرة عادت room/FFI listeners وstreams وconsumer jobs للصفر؛ المصدر
  مغلق ومؤقته متوقف، ولا failures مرصودة من منتج أو مستهلك PCM.
- صُورت `/proc` بعد settle طبيعي ثابت 2s لكل دورة، ثم 5s بعد مغادرة العميلين.
  فُصل إسقاط مرجع fixture الأخير وGC القسري عن قياس التنظيف الطبيعي.

[النتيجة الخام الكاملة والـFDs وأنواعها ومنافذها وRSS والبصمات](closure-stability-result.json).

| العملية | العينات | p50 ms | p95 ms | الأقصى ms |

| مغادرة A عبر IPC | 12 | 98.36 | 104.76 | 104.76 |
| اتصال ونشر A عند العودة | 12 | 130.83 | 249.26 | 249.26 |
| جاهزية PCM ثنائي الاتجاه بعد العودة | 12 | 437.70 | 814.05 | 814.05 |
| وقف توليد المصدر المحلي | 12 | 4.16 | 7.92 | 7.92 |

Percentiles بطريقة nearest rank؛ p95 لعينة من 12 يساوي أقصاها. زمن المغادرة عبر
IPC يتضمن انتظار fixture مقصودًا قدره 80ms بعد disconnect؛ لا يُنسب كله إلى SFU
أو التطبيق. وقت العودة يشمل IPC وتوليد token محلي وفحص PCM/FFT. لا مهلة منتج تغيرت.

وسيط جاهزية PCM لأول أربع دورات 463.87ms ولآخر أربع 440.17ms؛ وسيط المغادرة
98.28→99.22ms. لم يظهر تدهور زمني تراكمي في هذه العينة، مع تذبذب عودة منفردة
إلى 814ms. هذه ملاحظة محدودة، وليست SLA أو ضمانًا لجلسات طويلة أو شبكات الجوال.

## واصفات الملفات والذاكرة

تعداد FD ثابت من قراءة روابط `/proc`، مع استبعاد مدخل الدليل العابر الذي كان
يضخم raw `readdir` بواحد. baseline البارد 28 لكل عملية، ولا يُخلط مع تهيئة runtime
الأصلي الدافئة. B متصل عند عينات كل دورة، وA مفصول؛ حالتا الاتصال مختلفتان عمدًا.

هذه السلسلة لا تُظهر زيادة رتيبة غير محدودة، لكنها أيضًا **لا تعود إلى baseline
البارد عند كل مغادرة**. يجب تفسير الأنواع ومرحلة تهيئة runtime، لا قبول العدد وحده.

| المرحلة بعد مغادرة العميلين | A | B | الملاحظة |
| --- | ---: | ---: | --- |
| settle طبيعي 5s | 58 | 39 | A يحتفظ بـ19 UDP؛ لا UDP لدى B |
| إسقاط `lastRoom` الاختباري دون GC ثم 2s | 43 | 39 | A يحتفظ بـ4 UDP |
| GC تشخيصي واحد ثم 2s | 43 | 39 | لم ينخفض العدد مجددًا؛ لم نعتمد GC كنجاح للتنظيف الطبيعي |

الـUDP الأربعة الباقية تتصل جميعها بـ`172.31.1.29:53`، أي DNS، وليست منافذ SFU.
أرقام inode: 188013 و190528 و188973 و188975؛ timestamps والمنافذ المحلية محفوظة
في JSON. هذه **هوية endpoints مثبتة**؛ لا تثبت وحدها سبب بقاء استعلامات resolver
أو أنها انتهت قبل خروج العملية. [تحليل SDK المستقل](closure-sdk.md) يفسر runtime
والعزل بين SDK الاختباري ومسار الإنتاج، دون تحويل GC أو الخروج الطبيعي إلى برهان heap.

RSS لدى A ارتفع من 87,780 إلى 101,656KiB خلال عينات الدورات، ولدى B من 80,288
إلى 86,796KiB. يشمل ذلك runtime وV8/JIT وتخصيص FFT ومخازن PCM؛ لم يُقَس retained
heap، ولا يكفي ارتفاع RSS المحدود لإثبات تسرب أو نفيه. كل هذه القياسات محفوظة.

## التنظيف والسجل وحدود النتيجة

بعد النهاية كانت عضوية SFU واتصالات relay صفرًا، وحُذفت الغرفة. خرج العميلان
طبيعيًا بعد dispose بـcode 0 وsignal null دون forced kill. أُبلغ مالك SFU فورًا
فأوقفه وحذف runtime والمفاتيح الخاصة، وتحقق من خلو المنافذ؛
[دليل تنظيف WebRTC](closure-webrtc-cleanup.json).

سجّل Pion ثلاث رسائل discard لمرشح متأخر لا يطابق ICE ufrag الحالي عند
03:57:01.653–03:57:01.701 UTC. حُفظ ملخص بلا قيم ufrag أو أسرار في دليل التنظيف؛
لم تُخف الرسائل. اجتازت معايير التعافي الثلاثة، ولا تثبت هذه الرسائل وحدها خللًا
في المنتج؛ يلزم ربطها بأعراض أو فشل مسار قبل استنتاج ذلك.

لا تعديلات في منطق الصوت أو مهلة 45 ثانية أو CSS أو تحسينات المقاعد. لا Push
أو نشر. النتيجة: سلوك المغادرة والعودة وتعافي الإشارة اجتاز الحمل المحلي المحدود،
مع حدود FD/RSS والأجهزة ومسار التطبيق المبينة أعلاه؛ قرار الاعتماد مركزي مستقل.

## إعادة الإنتاج

في نافذة موارد حصرية، بعد تجهيز SFU المحلي المصحح بأسرار مؤقتة خارج المستودع:

```sh
VOICE_STABILITY_RUN=1 node tests/voice-acceptance/stability-soak.mjs \
  /tmp/tahaddi-closure-webrtc/runtime.json \
  docs/visual-evidence/live-room-responsive/closure-stability-result.json
```

السجل الفعلي: `/workspace/scratch/closure-stability.log`. السكربت يتطلب opt-in،
ويستخدم guard loopback والـport الثابت في orchestrator. لا يُجمع في suite العادي،
ولا يُشغّل بالتزامن مع الشاملة أو قواعد التكامل أو متصفح. نجح syntax وPrettier
و`git diff --check`؛ لم تُعد الجولة بعد نجاحها.
