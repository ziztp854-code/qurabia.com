## الأمر وإعادة التشغيل الآمنة

من جذر المستودع، بعد تخصيص نافذة المورد وعدم وجود خدمة أخرى على 55442:

```sh
VOICE_APPROVAL_RUN_INTEGRATION=1 node tests/voice-acceptance/run-integration.mjs --keep-container
```

[الـlauncher القابل للمراجعة](../../../tests/voice-acceptance/run-integration.mjs)
يستخدم Node و`pg` وDocker المحلي، ولا يُثبّت اعتماديات أو يُنزّل صورة. ينشئ أسماء
جديدة لكل تشغيل. بدون `--keep-container` يحذف الحاوية الخاصة وملفَي البيئة والحالة
والدليل المؤقت بعد انتهائه. بوضع الاحتفاظ تُسلّم قاعدة load فقط إلى الوكيل المختص؛
يتولى هذا الوكيل التنظيف بعد إشارة المنسق، لا `docker prune` ولا حذفًا عامًا.

```sh
node tests/voice-acceptance/run-integration.mjs --cleanup /tmp/voice-approval-integration-<run>/state.json
```

المسار مثال؛ التنظيف الفعلي يقبل ملف الحالة الخاص المولد لهذا التشغيل فقط، ويطابق
nonce وID الحاوية قبل حذفها وبياناتها المؤقتة. لا تُضبط متغيرات opt-in في `.env`
ولا يُغيّر إعداد دائم لتجاوز شروط الحماية الأصلية.

## مشكلة تهيئة مغلقة وليست فشل منتج

المحاولة الأولى لم تنفذ أي assertion: `pg_isready` عبر Unix socket التقط خادم
PostgreSQL المؤقت الذي تستخدمه الصورة أثناء init، ثم أعادت الصورة تشغيله قبل
`CREATE DATABASE`، فظهرت `database system is starting up`.

حُذفت الحاوية الخاصة وملفات الجلسة والحالة بالكامل. عُدّلت جاهزية الـlauncher فقط
لتنتظر TCP على `127.0.0.1`، لأن خادم init المؤقت يستمع socket فقط. أُعيدت التهيئة
مرة واحدة لهذا السبب المثبت؛ لم تُعَد اختبارات المنتج لأنها لم تبدأ في المحاولة
الأولى. [دليل المحاولة الأولى والتنظيف](approval-integration-setup-attempt-1.json).

لا تستخدم هذه الاختبارات نقل صوت حقيقيًا أو LiveKit حيًا، ولا تختبر ميكروفونًا أو
سماعة على جهاز مادي. هي دليل تكامل فعلي للبيانات والتزامن والهوية على PostgreSQL
محلي معزول. لا تثبت خصائص الشبكة أو الإبطال في SFU متعطل أو أداء الإنتاج تحت الحمل.

نجح فحص syntax وPrettier و`git diff --check` للـlauncher. ملفا هذه المهمة هما
الـlauncher والتقرير، مع JSON الأدلة؛ لا ملف إنتاج تغير. لا Push أو نشر.
