# حارس إصلاح ارتفاع المقاعد عند 200%

المراجع المستقل: `/root/accept_visual_guard`، بتاريخ 21 أكتوبر 2026.
المرجع: [تقرير التحقق السابق](final-acceptance.md).

**النتيجة: إصلاح ارتفاع المقاعد محفوظ واجتاز التحقق المستهدف المحلي.**
لم أعدل CSS أو مكونًا أو اختبارًا أصليًا، ولم أغيّر منطق الصوت أو مهلة 45 ثانية.
هذا تحقق عرض وتفاعل، ولا يعلن جاهزية الإنتاج أو نجاح الصوت على أجهزة حقيقية.

## حدود الملكية والموارد

- شُغّلت الجولة بعد انتهاء الجولة الشاملة ونافذة WebRTC، في نافذة متصفح حصرية
  وافق عليها المنسق، بعامل Chromium واحد وخادم fixture واحد على المنفذ 3417.
- استُخدمت نسخة مؤقتة مطابقة من الاختبار القائم في `apps/web/.reports` المعزول
  والمتجاهَل بواسطة Git. الاختلاف الوحيد في الاختبار هو وجهة الأدلة `approval-*`،
  لكي لا تُكتب ملفات `before-*` أو `final-*` السابقة من جديد.
- يتضمن config المؤقت تحديد working directory الصحيح للخادم في `apps/web`.
  محاولة الإعداد الأولى أخفقت قبل بدء أي اختبار لأن موضع config المؤقت غيّر cwd؛
  صُحح ذلك في config المؤقت فقط، ثم نُفذت الجولة الفعلية أدناه.
- لم يُشغّل متصفح أثناء الاختبارات الشاملة أو عملاء WebRTC/التحميل. بعد الانتهاء
  خرج Playwright برمز 0، وكان فحص اتصال TCP بالمنفذ 3417 سلبيًا؛ الخادم مغلق.

## الفحص البنيوي

تأكدت قراءةً من بقاء القاعدتين في `live-room-desktop.module.css`:

```css
min-block-size: min-content;
grid-template-rows: auto auto minmax(180px, 1fr) auto auto;
```

اختبار 200% لا يكتفي بـcenter-hit؛ يقيس الجزء المرئي من المقعد داخل تقاطع
العمود وmain والنافذة، ويشترط ارتفاعًا لا يقل عن 44px. كذلك يفحص النقر والتركيز
على الإرسال بعد التمرير، واستيعاب textarea لسطر النص المكبر وحشوه.

بصمة SHA-256 لملف Desktop قبل الجولة وبعدها متطابقة:
`b7da25d79f4a933a6b4ce006e5faaff79e6a2528b6f62cf858d14a26dc6a4e82`.
بصمات `live-room-mobile.module.css` و`live-room.module.css` و`voice-room.tsx`
و`e2e/live-room-responsive.spec.ts` كانت أيضًا متطابقة قبل الجولة وبعدها.

## قرار الحارس وحدود الدليل

لا عائق عرض جديد مثبت في السيناريوهين؛ إصلاح 8px ← 180px لم يتراجع. لا حاجة
لتعديل إنتاج أو إعادة تصميم أو إعادة مصفوفة مكلفة دون تغيير جديد يبررها.
لا أرفع تقييمًا بصريًا عامًا أو أستنتج موافقة إنتاجية من هذا الحارس المحدود.

المتصفح Chromium 151 محلي headless، DPR=1، و200% محاكاة بمضاعفة computed font sizes.
المكونات وCSS والأصول أصلية، لكن HTTP وAudioSession محاكيان في fixture. هذه النتائج
لا تثبت WebRTC حيًا أو صوتًا مسموعًا أو لوحة مفاتيح نظام حقيقية أو أداء جهاز محمول؛
أدلة WebRTC/التحميل والأجهزة يجب أن تُقرأ من تقاريرها المستقلة دون دمج الفئات.

نجح `git diff --check`. لم يُنفذ Push أو نشر أو تعديل مكون أو إعداد إنتاجي.
