# ضغط دورة الحياة وفحص الموارد بعد المغادرة

التاريخ: 21 أكتوبر 2026. المراجع المستقل: `accept_lifecycle`.
المرجع: [التحقق النهائي السابق](final-acceptance.md).

## النطاق والنتيجة

شُغّلت مكونات الإنتاج الفعلية `AudioSession` و`VoiceSessionProvider` وhooks
النافذة والطبقات داخل jsdom، مع SDK صوت وHTTP محاكيين قابلين لقياس الموارد.
**النتيجة النهائية: 8 اختبارات ناجحة، صفر فشل، صفر تجاوز، خلال 7.92s.**
لم تتغير ملفات الإنتاج أو مهلة المغادرة البالغة 45 ثانية.

لا اتصال SFU أو ميكروفون فعلي في هذه المجموعة. قياس انتهاء Room والمستمعين
والمؤقتات وDOM في هذا الاختبار ليس قياسًا للذاكرة المحتجزة في متصفح أو SDK حقيقي.
العميل المحاكى يحتفظ عمدًا بمراجع probes للاتصالات القديمة حتى نفحص تنظيفها؛
لذلك لا يصح استنتاج ثبات heap أو تحرير كل كائن من هذه الأرقام.

## النتائج المقاسة

[القياسات الآلية النهائية](approval-lifecycle.json).

| الحالة | الضغط المنفذ | النتيجة |
| --- | --- | --- |
| اتصال/اشتراك صوت بعيد/إعادة اتصال/توقف | 60 دورة، تتضمن 6 إعادات اتصال ناجحة | إنشاء 66 اتصالًا، وإيقاف 66 track؛ لا اتصال نشط أو SDK listener أو audio element أو timer بعد تنظيف كل دورة |
| طلب token معلق ثم مغادرة وإكمال متأخر | 30 دورة | إلغاء signals الثلاثين، ومنع إنشاء Room أو تشغيل الميكروفون من الاستجابة المتأخرة |
| رفض token مؤقت 409 ثم مغادرة | 30 دورة | إلغاء timer إعادة المحاولة؛ 30 طلبًا فقط، دون token أو اتصال لاحق بعد تمرير 60 ثانية افتراضية |
| storage lease بدون Web Locks | 20 دورة مع تجديد lease | إزالة lease وinterval؛ لا مورد متبقٍ بعد المغادرة والتنظيف |
| اكتمال تشغيل جهاز متأخر بعد المغادرة | حالة سباق مستقلة | track يبقى متوقفًا ومعطلًا، ولا يعود الاتصال |
| Provider: فتح غرفة ثم الانتقال للعبة ثم المغادرة | 20 دورة | استمرار الاتصال أثناء اللعبة، ثم توقفه فور المغادرة؛ صفر polling لاحق أو SDK/global listener أو lock أو timer متبقٍ |
| heartbeat HTTP معلق وقت المغادرة | حالة مستقلة | الوسائط المحلية تتوقف تزامنيًا، لكن HTTP read يبقى حتى مهلة القراءة 10 ثوانٍ ثم يُلغى؛ لا polling جديد أو اتصال أو timer بعد ذلك |
| viewport وoverlay | 30 دورة mount/unmount | صفر RAF أو ResizeObserver متبقٍ؛ 60 إضافة و60 إزالة لمستمعي visualViewport؛ إعادة overflow وتنظيف listeners |

المقصود بالتوقف الفوري هنا تحقق **في نفس استدعاء إجراء المغادرة، قبل await لإقرار
HTTP**: يصبح track معطلًا ومتوقفًا، ويُطلب disconnect، وتزال اشتراكات SDK وعناصر
الصوت البعيد. لم نسجل أرقام زمن حقيقية أو p95 لهذا التوقف باستعمال ساعة محاكاة.

استُخدمت مؤقتات اختبار حتمية وworker واحد. الاختبارات لا تنتظر wall clock ولا ترفع
مهلات المنتج أو تكرر حملًا خارجيًا. بعد كل دورة تُمرر 60 ثانية افتراضية للتأكد من
أن إعادة المحاولة أو مؤقت polling لم يعد يخلق طلبًا أو اتصالًا بعد المغادرة.

## الحد المثبت: ذيل HTTP محدود، وليس إلغاءً فوريًا لكل الطلبات

مستدعي `voiceRequest` الخاص بـheartbeat داخل `VoiceRoomView` لا يمرر owner
AbortSignal. إذا كان طلب القراءة معلقًا عند المغادرة، يتوقف الصوت ويُنظف المكون،
لكن طلب HTTP ومؤقت مهلة القراءة يظلان حتى انقضاء 10,000ms من بدء القراءة.

أثبت الاختبار عدم إلغائه فورًا، وبقاء signal غير ملغاة عند 9,999ms، وإلغاءها عند
10,000ms، ثم عدم بقاء timer أو اتصال أو إعادة polling بعد ذلك. هذا مورد ذو ذيل
محدود زمنًا في السيناريو المختبر، وليس دليلًا على تسرب غير محدود أو استمرار صوت.
إلغاء المتصفح لا يثبت إلغاء العمل الجاري على الخادم.

لم يُعدّل هذا المسار؛ المستخدم طلب عدم تغيير منطق الصوت أو مهلة المغادرة دون
إثبات الحاجة وموافقته. إن كان معيار الاعتماد يتطلب إلغاء **كل HTTP request**
تزامنيًا عند الخروج، فهذا الحد يبقى مفتوحًا ويحتاج قرارًا مستقلًا؛ لا تُحوّل
نتيجة المجموعة إلى ادعاء «صفر موارد فورًا» لجميع الطبقات.

## الأوامر وملكية الملفات

من `apps/web`، بعد منح المنسق نافذة موارد حصرية وانتهاء الجولة الشاملة والتكامل:

```sh
node node_modules/vitest/vitest.mjs run --config vitest.voice-lifecycle.config.ts
```

السجل النهائي: `/workspace/scratch/voice-approval-lifecycle.log`.
الأدلة تُكتب من مسار محلي محدد في config؛ لا أسرار أو إعدادات إنتاج.

الملفات المضافة المملوكة لهذا الوكيل:

- `tests/voice-acceptance/lifecycle-stress.test.tsx`
- `apps/web/vitest.voice-lifecycle.config.ts`
- هذا التقرير و`approval-lifecycle.json`

ملف الاختبار خارج include المجموعة العادية `src/**/*.test.{ts,tsx}`، لكيلا تبدأ
عملية stress إضافية تلقائيًا أو تتنافس مع جولة المشروع الشاملة. لا حزم جديدة.

في المحاولة الأولى نجحت الاختبارات الثمانية، لكن hook كتابة دليل `afterAll`
أخفق لأن Vite حوّل `import.meta.url` إلى عنوان HTTP. صُحح مسار الدليل في config وhook كتابة الدليل
فقط، وأُعيدت المجموعة القصيرة: **8/8 وexit 0**. لم تُغير assertions لتنجح.

تحقق Prettier و`git diff --check` ناجح. ESLint للملفين exit 0 بلا أخطاء؛ عند
استدعائه من جذر monorepo أبلغ رسالتي إعداد عن اكتشاف React ومجلد Pages في الجذر،
لا عيبًا في الملفين. لم يُشغّل أو يُعدّل أي تطبيق/قاعدة/SFU حقيقية في هذه المجموعة.

## أثر الاعتماد

لم يُرصد نمو دائم في الموارد المرصودة عبر دورات التنظيف المحددة، وثُبت منع
التشغيل المتأخر للميكروفون وإعادة الاتصال بعد التوقف. يبقى HTTP tail موثقًا،
وتبقى مراقبة موارد SDK/ICE/SFU الحقيقية وheap والأجهزة الفعلية أدلة منفصلة.
لم يُنفذ Push أو نشر أو تغيير إنتاجي، ولا تمنح هذه المجموعة وحدها موافقة إنتاجية.
