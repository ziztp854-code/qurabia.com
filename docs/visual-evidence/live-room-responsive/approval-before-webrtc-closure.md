# استكمال اعتماد شاشة البث الصوتي

التاريخ: 21 أكتوبر 2026. المرجع السابق: [final-acceptance.md](final-acceptance.md).
الأساس `2eee844eea20cb07389723e157e684bcc7c14410` مع تغييرات العمل المحلية المحفوظة.

**القرار: أُغلقت فجوات الاختبارات الشاملة والتكامل المحلي، وبقي اعتماد الإنتاج معلّقًا.**
نجح نقل WebRTC حقيقي بإشارة صوت مولدة في إعداد أول، لكن إعادة حصر الوسائط على
loopback أخفقت؛ لم يُثبت سبب الإخفاق أو تحرير جميع واصفات الملفات داخل العملية.
لا موافقة صريحة على قبول هذه المخاطر، ولا Push أو نشر أو تغيير لمنطق الصوت أو مهلة 45 ثانية.

## المهلات الخمس ومهلة المغادرة

اجتازت الحالات الخمس التي تعثرت سابقًا الجولة الشاملة الحالية نفسها. اختبار
الدردشة القديم استهلك 2000+2500ms انتظارًا حقيقيًا داخل مهلة Vitest قدرها 5000ms؛
التعديل الحتمي السابق حافظ على assertions ونجح الآن في 575ms. الاختبارات الأربعة
الأخرى نجحت دون تغييرها؛ يدعم ذلك أثر الجدولة والتنافس على CPU، لكنه لا يثبت
السبب الوحيد لكل تعثر قديم. لا خلل سلوكي مثبت يستدعي تغيير إنتاج الصوت.

مهلة `/leave` البالغة **45000ms بقيت كما هي**؛ ليست مهلة Vitest البالغة 5000ms.
نجح اختبار المغادرة المقوّى، بما فيه وقف الوسائط المحلية تزامنيًا وبقاء الطلب
معلقًا عند 10,000 و44,999ms ثم إلغائه عند 45,000ms وإتاحة الإعادة الصريحة دون reconnect.
هذه سياسة عميل، وليست ضمان إنهاء عمل الخادم أو SFU خلال المدة.
[التحليل المفصل](approval-suite.md) و[تحقيق العقد الأصلي](final-leave-timeout.md).

## الحمل والمغادرة والموارد

نفذ الحمل HTTP حقيقيًا على قاعدة جديدة: مضيف وأربعة مستخدمين، خمس دورات من الدخول
واستعادة سياق HTTP وإعادة الدخول والمغادرة؛ **80/80** خلال 7.54s، وصفر أخطاء.
بلغ leave ‏p95=434ms وأقصاه 473ms. بعد كل دورة عادت العضوية إلى المضيف وحده، دون
تكرار، مع تطابق API وPostgreSQL. استعادة سياق HTTP ليست إعادة اتصال صوتية.
الأرقام لحمل محدود وخادم تطوير دافئ؛ ليست سعة إنتاج أو SLA.

اختبارات دورة الحياة غطت 60 دورة AudioSession و6 إعادات اتصال، و30 طلب token معلقًا،
و30 إعادة محاولة صلاحية، و20 lease، و20 دورة Provider، و30 mount/unmount للنافذة.
عادت الاتصالات والمستمعات والمؤقتات وعناصر الصوت المرصودة للصفر بعد تنظيفها؛
مُنع تشغيل الميكروفون المتأخر بعد المغادرة. الإثبات هنا لمكونات التطبيق مع SDK محاكى.

**الاستثناء المثبت:** طلب heartbeat الجاري قد يبقى حتى انتهاء مهلة قراءته 10s
من بدء الطلب، رغم التوقف التزامني للوسائط المحلية. يُلغى عند المهلة ولا يعاود polling.
هذا ذيل محدود في الحالة المختبرة، وليس «صفر موارد فورًا»، ولا دليل تسرب غير محدود.
لم يُعدّل المسار؛ يلزم قرار مستقل إذا اشترط الاعتماد إلغاء كل HTTP request فورًا.

## WebRTC الفعلي وحدود الإثبات

استخدم الاختبار خادم LiveKit 1.13.10 من صورة رسمية مثبتة بالبصمة، وعمليتي Node
مستقلتين باستخدام native WebRTC. نُقل PCM مولد 440/660Hz وفُك ترميزه في الاتجاهين.
المحاولة الأولى أثبتت أيضًا توقف المصدر المولد قبل disconnect، وهدوء الطرف الآخر
بعد هامش تصريف معلن، واستعادة النقل بعد قطع WebSocket فعلي، وثلاث دورات مغادرة وعودة.
أُغلقت العمليتان طبيعيًا برمز 0، وعادت عضوية SFU واتصالات relay إلى الصفر.

فحص العزل اكتشف أن `bind_addresses` قيّد الإشارة فقط، وأن RTC استمع على واجهات
أوسع؛ لم تُستخدم أجهزة خارجية. صُحح **إعداد الاختبار فقط** لحصر UDP على loopback
وتعطيل TCP fallback، ثم أُعيد مرة لسبب مثبت. نجح الاتصال والنشر، لكن PCM لم يصل
ضمن الحد الأصلي. فرضية استبعاد loopback في جمع ICE غير مثبتة لغياب تشخيص مرشحي ICE؛
لا نضعها سببًا جذريًا ولا نرفع المهلة. حُفظت المحاولتان، ولم تُجر جولة ثالثة بلا دليل.

صفر listeners/streams/jobs/source timers لا يثبت خلو SDK الأصلي من التسرب:
**واصفات الملفات لم تعد إلى baseline أثناء بقاء العمليات**. الخروج الطبيعي يحرر
موارد العملية، لكنه لا يغلق سؤال الاحتجاز أثناء جلسة طويلة. اسم معيار baseline
في نتيجة المحاولة الأولى يخص عدادات الوسائط المرصودة، ولا يشمل FD أو heap.
[التشخيص والقياسات وحدود النقل](approval-webrtc.md).

النقل الحقيقي بإشارة مولدة ليس محاكاة SDK، لكنه لا يثبت السماع على أجهزة فعلية،
ولا يشغّل browser AudioSession أو بوابة قبول الغرفة وإبطال صلاحياتها الإنتاجية.
نجاح HTTP ونجاح native SFU دليلان منفصلان؛ رحلة التطبيق الكاملة بينهما غير مثبتة.

## المقاعد والصور والنص 200%

نجحت حالتا المتصفح المستهدفتان بعامل واحد، دون تغيير ملفات الإنتاج. عند 1440×900
والنص 200% بقي صف المقاعد والجزء المرئي 180px؛ وعلى 320×700 بقي الجزء المرئي
233.36px. نجح hit testing والتركيز للمقعد والإرسال؛ انتهى زر الإرسال على الكمبيوتر
عند 720.75px قبل الأدوات 738px. لا تصادم للمقاعد الثمانية أو تمدد للصور أو تداخل
مع الدردشة والأدوات في الحالتين المختبرتين، والإدخال قابل للوصول بالتمرير.

حُفظ إصلاح `minmax(180px, 1fr)` و`min-block-size: min-content`، وتطابقت بصمات CSS
ومكونات الغرفة وspec قبل التحقق وبعده. لم تُكرر مصفوفة المقاسات الـ14 لأنها اجتازت
المرحلة السابقة ولم يتغير المصدر. [المراجعة والصور الجديدة](approval-visual.md)
تربط أيضًا بصور قبل الإصلاح وبعده. تكبير computed text ومحاكاة viewport ليسا
دليل لوحة مفاتيح أو إعداد وصول على هاتف فعلي.

## استقلال الوكلاء وجدولة الموارد

| الوكيل | ملكيته المستقلة |
| --- | --- |
| `accept_suite` | تقرير الجولة الشاملة وبصمات نتائجها؛ لا تعديل للمصدر |
| `accept_integration` | launcher قواعد الاختبار، نتائج التكامل وتنظيفها |
| `accept_lifecycle` | stress test وconfig اختياري مستقل وقياسات الموارد |
| `accept_load` | خادم وعميل الحمل والرسم وقياسات HTTP |
| `accept_webrtc` | إعداد SFU وعميلان وorchestrator وأدلة المحاولتين |
| `accept_visual_guard` | تقرير العرض والصور الجديدة؛ دون تعديل CSS |

جرى التحضير والمراجعات بالتوازي، مع نوافذ ثقيلة متتابعة: الشاملة، التكامل، دورة
الحياة، حمل API، نقل SFU، ثم المتصفح. تولى المنسق الدمج وملفات التقارير المشتركة.
لم يُشغّل حملان على قاعدة أو منفذ أو ميزانية موارد واحدة في الوقت نفسه.

الإعادات المبررة فقط: تصحيح جاهزية PostgreSQL قبل بدء assertions، وتصحيح مسار
كتابة دليل lifecycle بعد نجاح حالاته، وإعادة عزل SFU. تعثر config المتصفح المؤقت
قبل بدء الاختبارات صُحح دون تغيير المنتج. لم تُكرر الجولة الشاملة أو حمل API بعد نجاحهما.

حُذفت حاوية PostgreSQL الخاصة وقواعدها وملفات env/state، وخادم Next وسياقات HTTP
وملف سر الحمل. أُغلقت عملاء SFU والـrelay والخادم، وحُذفت ملفات مفاتيحه المؤقتة.
أُغلق fixture والمتصفح؛ لا تنظيف عام لحاويات أو صور مشتركة.
[دليل تنظيف قاعدة الاختبار](approval-integration-cleanup.json) وتفاصيل كل مورد
في تقريره المستقل. تحقق المنسق من بصمات ملفات الجولة الشاملة وJSON وروابط الأدلة
وsyntax للأدوات و`git diff --check`؛ لم تتغير الملفات المختبرة بما يستدعي جولة شاملة أخرى.
[التحقق المركزي من syntax وإغلاق المنافذ وحذف الأسرار](approval-central-verification.json).

## المخاطر المتبقية وقرار القبول

أُغلقت محليًا: الإخفاقات الخمسة في الجولة الشاملة، وفجوة الـ17 الاختيارية، وثبات
عضوية الغرفة تحت الحمل المحدود، وحارس ارتفاع المقاعد عند 200%، وتنظيف موارد
التطبيق المرصودة مع حد HTTP الموثق.

يبقى اعتماد الإنتاج معلّقًا لحين إغلاق أو قبول المخاطر التالية صراحةً:

- تعثر PCM في إعداد SFU المعزول وغياب تشخيص ICE حاسم؛ لا دليل على خلل إنتاجي محدد بعد.
- احتجاز واصفات SDK داخل العملية يحتاج تشخيصًا/soak؛ العدادات الحالية لا تثبت غياب كل تسرب.
- عدم اختبار المسار الكامل عبر بوابة التطبيق مع صوت حقيقي وإبطال الصلاحيات، خصوصًا عند تعطل SFU.
- عدم تنفيذ صوت الجهازين ولوحة مفاتيح جوال حقيقيين، وعدم إثبات سعة إنتاج أو تنوع شبكات.
- ذيل heartbeat المحدود وكون مهلة 45s لا تلغي بالضرورة عمل الخادم الجاري.

لا تغيير إنتاجي جديد في هذه المرحلة؛ إضافاتها أدوات اختبار وأدلة قبول فقط.
حُفظت جميع تعديلات الواجهة والاختبارات السابقة. لم تُجر عملية commit أو Push أو نشر.
