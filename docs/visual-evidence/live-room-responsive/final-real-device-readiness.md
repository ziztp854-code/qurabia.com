# التحقق من توفر الأجهزة الحقيقية

المراجع المستقل: `final_hardware`. المرجع: [تقرير إصلاح الشاشة](README.md).
وقت الجرد: **21 أكتوبر 2026، 06:10 بتوقيت الرياض** (03:10 UTC).

## النتيجة

**اختبار الصوت بين جهازين حقيقيين واختبار لوحة مفاتيح جوال حقيقي غير منفذين.**
لم يُعثر في بيئة التنفيذ أو أدوات الجلسة المتاحة على أجهزة فعلية متصلة يمكن تشغيل
الاختبار عليها. كذلك لا توجد إعدادات LiveKit محلية جاهزة في هذه اللقطة.
هذا نقص في دليل الاعتماد، وليس اختبارًا فاشلًا أو اختبارًا ناجحًا بالمحاكاة.

| الاختبار المطلوب | الحالة | السبب المثبت |
| --- | --- | --- |
| كلام ثنائي الاتجاه بين جهازين وميكروفونين حقيقيين | **غير منفذ** | لا جهازان متصلان، لا واجهة صوت مادية متاحة، ولا SFU محلي مهيأ |
| فتح لوحة مفاتيح النظام وإغلاقها على جوال حقيقي | **غير منفذ** | لا هاتف Android أو iOS متصل ولا جلسة اختبار أجهزة فعلية متاحة |
| جرد توفر الأجهزة والخدمات | **منفذ** | فحوص نظام الملفات والأدوات والمنافذ وحالة البيئة موثقة أدناه |

لا تُحتسب نافذتا Chromium على هذه الآلة جهازين حقيقيين. ولا تُحتسب مصادر PCM
مولدة، أو `fake media`، أو تعديل `visualViewport`، أو وضع mobile emulation بديلًا
عن أي من الاختبارين المطلوبين.

## الأدلة الفعلية

جردتُ البيئة بأوامر قراءة فقط، دون تشغيل متصفح آخر أو SFU أو Docker ودون تغيير إعدادات.

| الفحص | النتيجة المرصودة |
| --- | --- |
| نظام التشغيل | Linux، x86_64 |
| `/dev/bus/usb` و`/sys/bus/usb/devices` | غير موجودين؛ لا أجهزة USB متاحة للجلسة |
| `adb` و`idevice_id` و`ideviceinfo` | غير مثبتة/غير موجودة في PATH |
| `xcrun` و`simctl` | غير موجودين؛ البيئة ليست مضيف اختبار iOS |
| منفذا ADB وAppium المحليان 5037 و4723 | لا خدمة تستمع عليهما وقت الجرد |
| `/dev/snd` و`/proc/asound/cards` | غير موجودين؛ لا أجهزة ALSA معروضة للبيئة |
| PulseAudio وPipeWire | لا socket مستخدم محلي؛ وأدوات `pactl` و`pw-cli` غير متاحة |
| `arecord` و`aplay` | غير متاحين |
| `/dev/video*` | لا أجهزة معروضة؛ هذا فحص جرد مساعد فقط، والكاميرا ليست مطلوبة للصوت |
| Chromium | متاح في `/usr/bin/chromium`؛ لا يثبت وجود هاتف أو ميكروفون فعلي |
| حالة البيئة المدارة | `running` و`observations_current=true` و`capabilities=[]`؛ لا هويات خارجية مهيأة |
| أدوات جلسة أجهزة فعلية | لم يوجد في كتالوج الأدوات القابل للاستدعاء موصل جهاز/جلسة هاتف أو أداة Browser `js` |

قُرئت مهارة Browser قبل الحكم على إمكانية الاتصال. أُجري بحث في كتالوج الأدوات
عن `setupBrowserRuntime` و`list_tabs` و`get_tab_context` و`nodeRepl` و`device` و`__js`؛
لم تظهر أداة يمكنها إنشاء جلسة تحكم بهاتف متصل. وجود وصف المهارة وحده لا يثبت اتصال
المتصفح أو امتلاك الوصول إلى جهاز المستخدم. لا يدّعي هذا الجرد عدم امتلاك المستخدم
أجهزة خارج الجلسة؛ فقط أنها ليست متاحة لهذه المهمة من خلال الأدوات الحالية.

### جاهزية الخدمة المحلية

فُحص حضور المتغيرات فقط في العملية، ثم بتحميل ملفات `.env` المحلية المدعومة عبر
Node دون طباعة القيم. لم تُفتح ملفات الأسرار لاستعراض محتوياتها.

- `LIVEKIT_MODE` و`LIVEKIT_URL` و`LIVEKIT_INTERNAL_URL` و`LIVEKIT_API_KEY`
  و`LIVEKIT_API_SECRET`: غير مضبوطة في بيئة الاختبار المحلية المحملة.
- متغيرات ربط الجهاز أو مزود أجهزة الاختبار `ANDROID_SERIAL` و`ADB_SERVER_SOCKET`
  و`APPIUM_SERVER_URL` وبيانات BrowserStack/Sauce: غير مضبوطة.
- الملفات السابقة الموصوفة في [audio-local.md](../../voice/audio-local.md)، وهي
  `/tmp/tahaddi-voice-local/livekit-server` و`livekit.yaml` و`session.env`، غير موجودة
  في هذه اللقطة. لم تُحاول إعادة استخدام أسرار من بيئة سابقة.
- المنافذ المحلية 3000 و3417 و7880 و7881 و7891 لم يكن عليها مستمع وقت الجرد.
  هذا قياس لحظة الجرد؛ يجوز أن يبدأ وكيل QA خادم عرض محليًا لاحقًا، ولا يعني ذلك
  توفير خدمة SFU أو جهاز حقيقي.

أمثلة الأوامر المنفذة فعليًا: جرد `shutil.which` للأدوات المذكورة، وفحص
`Path.exists` و`glob` لمسارات الأجهزة، و`socket.connect_ex(('127.0.0.1', port))`
للمنافذ المحددة، ثم:

```sh
node --env-file-if-exists=.env --env-file-if-exists=.env.local \
  --env-file-if-exists=apps/web/.env.local --input-type=module
```

استُخدم البرنامج الداخلي لهذا الأمر لإخراج `Boolean(process.env[name])` فقط للأسماء
المحددة أعلاه وفحص وجود ملفات الإعداد المذكورة. لم تُطبع أي قيمة اعتماد أو رمز اتصال.

## المطلوب لإغلاق فجوة الدليل

1. إتاحة جهازين ماديين مستقلين بميكروفون وسماعة، مع تسجيل طراز كل جهاز ونظامه
   ومتصفحه. يفضَّل تضمين iPhone/Safari وAndroid/Chrome لتغطية لوحة المفاتيح، مع
   شبكتين مختلفتين لاختبار الاتصال كما تتطلب [وثيقة القبول](../../voice/acceptance.md).
2. إتاحة أصل HTTPS اختبار مصرح به يصل إليه الجهازان، وSFU مع بوابة الانضمام الصحيحة
   أو إعداد LiveKit Cloud صالح، وحسابي اختبار مستقلين وغرفة معزولة. لا يتضمن هذا التقرير
   إذن نشر أو تغيير إعدادات الخدمات أو استخدام بيانات الإنتاج.
3. تنفيذ كلام حقيقي في الاتجاهين، ثم الكتم وإلغاؤه، تغيير صلاحية المقعد، المغادرة،
   وانقطاع الشبكة والعودة؛ التأكد من توقف الصوت عند المغادرة وعدم وجود صوت مكرر أو
   جلسة ميكروفون ثانية. تستمر المحادثة أثناء تغيير المقاس والتنقل داخل التطبيق.
4. على الجوال الفعلي: فتح حقل الرسالة ولوحة مفاتيح النظام، الكتابة والإرسال والإغلاق
   وإعادة الفتح، ثم التدوير بين الأفقي والرأسي. توثيق عدم حجب الإرسال أو الأدوات أو
   المقاعد، واستمرار الصوت، وعودة مساحة العرض والتركيز بعد الإغلاق.
5. حفظ نتيجة كل خطوة مع الجهاز/النظام/المتصفح والشبكة ووقت الاختبار، وصور الفتح والإغلاق
   وملاحظات السماع من الطرفين. لا يلزم تسجيل كلام المستخدمين أو حفظ رموز الدخول.

## أثر القرار

تبقى المصادقة على الصوت المسموع وسلوك لوحة المفاتيح الفعلية **مفتوحة** إلى أن تُنفذ
هذه الخطوات على أجهزة حقيقية. نجاح الاختبارات المحلية أو الصور لا يغلقهما، ولا يبرر
إعلان جاهزية الإنتاج. يلزم توضيح هذا الخطر والحصول على موافقة المستخدم قبل أي اعتماد
للإنتاج. لم يُنفّذ Push أو نشر أو تغيير لمنطق الصوت أو ملفات الإنتاج ضمن هذا الجرد.
