- حاويتا PostgreSQL وRedis جديدتان فقط، من صور محلية مثبتة بالـimage ID و`--pull=never`.
  PostgreSQL: `sha256:79bd7c99e923138f136f8009d6bffa66e21e9d4fda5c0c561b00fc9c90cfe537`؛
  Redis: `sha256:f84b0c4678011602b9b98c227a4dcd5468bf8b088b02fdd4165cb7758bad8058`.
- الربط `127.0.0.1:55443` و`127.0.0.1:56380`؛ لم نستخدم 5432 أو 6379 القائمين.
  التخزين tmpfs دون host data mounts، ودون قاعدة تطبيق أو حساب أو خدمة إنتاج.
- قاعدة `kingdoms_test_closure_a13744d8f384` جديدة طُبقت عليها 32 migration؛
  و`openclaw_approval_test` جديدة داخل الحاوية الخاصة يبني اختبارها schema الخاص به.
  Redis جديد بلا persistence؛ PostgreSQL وRedis phases متتابعتان.
- كلمة مرور PostgreSQL مولدة عشوائيًا في ذاكرة العملية؛ لا ملف env أو مفاتيح جلسة
  أُنشئت على القرص، وعناوين الاختبار لا تُستمد من `DATABASE_URL` الخاص بالمشروع.
- بعد النتائج، طابق التنظيف label nonce وcontainer ID لكل حاوية قبل حذفها. فحص
  `docker ps -a` بمرشحي الاسمين أعاد قائمة فارغة، والمنفذان مغلقان فعليًا.
  لا `docker prune` أو حذف صور/حاويات مشتركة.

## لماذا بقي Blender غير منفذ؟

Blender موجود في البيئة، لكن اختبار watch يعيد نشر `manifest.json` وملفات models
ويغير mtime لمشهد قائم. لا يضيف دليلًا لمخاطر الصوت، وقد يتداخل مع أصول المستخدم.
قرر المنسق استبعاد الاختبارين من مهمة إغلاق الصوت؛ لم نُعدّل اختباريهما أو شروطهما،
ولم نُشغّل texture test منفردًا لتجميل عدد المتجاوزات. ليسا اختبارات فاشلة أو ناجحة
في هذه المرحلة؛ حالتهما **غير منفذين** صراحةً.
