# تجربة Visual Excellence — سوق قرية الممالك

نفذت التجربة محليًا على مكونات التطبيق الفعلية داخل fixture القرية القائم، مع محرك اللعبة المحلي والخطين Cairo/Alexandria نفسيهما. لم تتغير قواعد اللعبة أو البيانات الدائمة أو إعدادات الإنتاج، ولم يحدث commit أو push أو نشر.

## ما تغير ولماذا

- صورة السوق الحالية متماسكة في الإضاءة والخامات والمنظور؛ أعيد استخدامها بدل توليد بديل غير لازم. الأصل **1672×941**، وليس 4K أو 8K. لم تُضف تفاصيل مصطنعة أو تكبير.
- فصل العرض الفني عن لوحة تجارة أكثر انتظامًا، وعنوان Alexandria وحد ذهبي هادئ من هوية الممالك، وأزرار دون توهج زائد.
- حقول الموارد تستعمل مجموعات مشتركة وRTL؛ تتحول التسميات فوق المدخل عندما تضيق المساحة. عند تكبير الخط إلى 200% اختبرنا قراءة `50000` فعليًا وقياس عرض النص، وأزلنا الشريط الثابت الذي كان يحجب الجوال.
- الجوال يعرض التكوين الأفقي كاملًا بدل صورة عمودية تشغل الشاشة وتؤخر الإدارة. التابلت يستعمل تدفقًا رأسيًا متوازنًا؛ الوضع الأفقي القصير يحتفظ بعمودين قابلين للتمرير.
- أضيف رمز مركزي لحدود الحقول يحقق نحو **3.31:1** مع السطح الخارجي، مقابل 2.63:1 سابقًا. تباين النص/السطح 9.76:1، والنص الثانوي 6.92:1، والذهب 6.03:1، ونص الإجراء 7.31:1.
- أصول WebP/AVIF بعروض 768/1280/1672 مع اختيار بحسب العرض وDPR، دون تحميل صورة المعاينة القديمة التي لا تُستخدم. المصدر محفوظ، و[سجل الأبعاد والأحجام](../../../apps/web/public/game-art/kingdoms/city-scenes/market-renditions.json) يتيح التحقق من الدقة المرمزة.

## نتائج قابلة للتحقق

- Playwright: **6 اختبارات ناجحة**؛ خمسة أحجام مع الصورة والخطوط والحقول وأهداف اللمس والعودة بـEscape وعدم التمرير الأفقي وتكبير الخط. اختبار إضافي يبني السوق عبر محرك fixture الموجود، وينشر عرضًا تجاريًا ثم يلغيه ويتحقق من الحالة. اختبرت أيضًا رسالة رفض السوق غير المبني دون تجاوز قواعده.
- **صفر مخالفات axe** داخل مشهد السوق مع WCAG A/AA و2.1 AA على الأحجام الخمسة. هذا لا يغطي إتاحة canvas أو قارئ شاشة فعلي أو الموقع كله.
- اختبارات المكونات المستهدفة: **7 ناجحة**؛ ESLint للملفات المعدلة ناجح. Build الويب، بما فيه TypeScript وتوليد الصفحات وفحص التعرض العام وميزانية ألوان CSS، ناجح. احتاج البناء الأول إعادة بناء الحزم المشتركة القديمة في البيئة؛ لم تُعدل مصادر تلك الحزم.
- ctxlint المطلوب: الأمران ناجحان، صفر أخطاء وتعليق واحد عن ميزانية طول AGENTS؛ فحص MCP لم يجد إعدادات.
- [قياس قبل](before-performance.json) و[قياس بعد](after-performance.json): صورة الكمبيوتر 571,464 → 166,739 بايت (**−71%**)، وصورة الجوال 446,010 → 72,899 (**−84%**) عند DPR1. سجل كل جهاز يسرد طلب الصورة الفعلي وأبعاد العرض؛ `densityCorrectedIntrinsic` هي أبعاد DOM المصححة للكثافة، وليست الأبعاد المرمزة للملف.
- Chromium **151.0.7922.173**، headless، SwiftShader، خادم محلي دافئ وسياق متصفح جديد لكل قياس، 120 فاصل rAF والحركة العادية: الوسيط **16.7ms** وp95 **16.8ms** قبل وبعد. هذا تتابع callbacks للمشهد الثابت وليس قياس FPS للعبة على هاتف فعلي. أزمنة تحميل 3.4–4.5ms محلية، ولا تمثل الإنترنت.

## إعادة التشغيل

من جذر المستودع:

```sh
node scripts/prepare-market-art.mjs
cd apps/web
pnpm exec playwright test --config playwright.visual-excellence.config.ts
```

يستخدم الاختبار fixture مستقلًا على 3314 ويغلقه بعد الانتهاء. اضبط `CHROMIUM_PATH` إذا كان المتصفح في مسار آخر؛ لا يحتاج الأداة لتنزيل متصفح جديد هنا. ستعيد الاختبارات كتابة أدلة «بعد»، لذلك تجب إعادة المراجعة إذا تغير المصدر.

لقياس الأداء، شغّل fixture القائم على 3310 من `apps/web` ثم `node scripts/capture-market-performance.mjs after` من الجذر. قيمة `before` تقيس **المصدر الحالي** ولا تستعيده تلقائيًا؛ لا تستخدمها كمرجع قبل التعديل إلا في نسخة مطابقة للـcommit المرجعي أعلاه. [بصمات المصدر والأدلة](evidence-manifest.json) تربط هذا التقرير بالملفات المعاينة.

## حدود الاعتماد

مشهد السوق صورة ثابتة مستقلة ولا يملك زومًا تفاعليًا؛ لم تُغير كاميرا المدينة أو هندستها. الدقة القصوى المتاحة 1672px وتحد اختيار نسخة DPR مرتفعة؛ لا وعد بتفاصيل جديدة عند التكبير. لم يُختبر WebP على متصفح يفتقر إلى AVIF أو Safari/Firefox أو زوم المتصفح الأصلي؛ اختبار 200% يكبر الخط الجذري ولا يحاكي جميع إعدادات الجهاز. بقيت ملاحظات طفيفة بشأن الفراغ تحت الصورة على الكمبيوتر واكتشاف إجراء النشر بالتمرير. المصادقة والإنتاج والأجهزة الفعلية خارج هذا التحقق المحلي.
