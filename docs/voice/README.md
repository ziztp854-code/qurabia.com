# تحدي لايف — نسخة مراجعة محلية

تطوير مستقل في فرع `feat/tahaddi-live-platform`، أذن المستخدم برفعه ونشره بعد المراجعة المحلية. يوضح [دليل النشر](production-deployment.md) المشروع وهجرة الجداول وحدود تشغيل الصوت. المسارات `/voice` و`/voice/[roomId]` جزء من تطبيق Next.js الحالي؛ تستخدم حسابات NextAuth وPrisma الحالية، دون حسابات ضيوف أو نظام عضويات مكرر. لا توجد مدفوعات أو عملات جديدة، ولا يُسجّل الصوت.

## البنية

- `src/components/voice`: واجهات الاستكشاف والإنشاء والغرفة والمقاعد والدردشة والصوت، في الكمبيوتر والجوال.
- `src/lib/voice`: عقود TypeScript، تحقق Zod، حالات الغرف وصلاحياتها، مستودع Prisma وتكامل LiveKit.
- `src/app/api/voice`: جلسات الحسابات الحالية، API الغرف والأحداث والتفضيلات والأغلفة وتهيئة الصوت وWebhook.
- `VoiceRoom`: حالة غرفة محدودة الحجم بإصدار CAS لمنع سباق المقاعد والتغييرات. `VoicePreference` للتفضيلات والسجل، `VoiceReport` للبلاغات وأدلتها، و`VoiceCover` لأغلفة مصغرة معاد ترميزها.
- الحضور والدردشة ينتقلان عبر استعلامات دورية متسلسلة كل ٢٫٥ ثانية. الصوت نفسه ينتقل عبر SFU في LiveKit، وليس عبر الاستعلامات أو Socket.IO.
- تقييد الأحداث، الجلسات، صلاحيات الأدوار، الغرف الخاصة، كلمات المرور والدعوات تُفرض من الخادم. بطاقات الغرف وأعداد الحاضرين تعتمد على البيانات الفعلية فقط.

## استمرار المايك مع الألعاب

تعيش الجلسة في `VoiceSessionProvider` داخل تخطيط التطبيق الأساسي؛ فتح لعبة عبر روابط الموقع يخفي واجهة الغرفة مع إبقاء اتصال LiveKit والميكروفون والحضور والتحقق من الصلاحيات. يتيح شريط مشترك فتح الألعاب، كتم المايك والسماعات، تغيير أجهزة الصوت، العودة إلى الغرفة ومغادرة الصوت دون مغادرة اللعبة. الانتقال لغرفة صوتية أخرى يتطلب اختيار التبديل صراحةً.

لا يفتح الموقع المايك لمجرد زيارة الألعاب، ولا تُحمّل حزمة LiveKit قبل فتح غرفة. الاستمرار يشمل التنقل داخل التطبيق في التبويب نفسه والألعاب المضمنة؛ إعادة تحميل المستند أو إغلاق التبويب تنهي الاتصال. لا تُحفظ حالة التشغيل لإعادة فتح المايك تلقائيًا بعد إعادة التحميل. تفاصيل الفحص في [سجل استمرار الصوت](persistent-voice.md).

## الصور والهوية

الألوان المحددة في الطلب معزولة ضمن رموز `--voice-*` في `apps/web/tokens.css`. تستخدم الواجهة خطي المشروع العربيين Cairo/Alexandria وتراعي RTL ومساحات الأمان والحركة المخفضة.

الأغلفة في `apps/web/public/voice/covers` مولّدة لهذا المشروع بأداة OpenAI image generation، وليست صورًا من منصة أخرى أو مضيفين حقيقيين. تشمل استوديو الميكروفون، المجلس، القهوة، الألعاب، العود، الحوار والمسابقات. الصور النهائية WebP محلية ونسخ `-mobile.webp`؛ لا روابط مؤقتة. مجموع النسخ نحو ٧٨٥ كيلوبايت.

الغلاف المرفوع يُقبل فقط JPEG/PNG/WebP بحجم لا يتجاوز ٢ MiB. يعاد فك ترميزه وتصغيره وإزالة EXIF ثم حفظ WebP بحد ٣٥٠ ألف بايت داخل قاعدة البيانات، بحد ٢٠ غلافًا للحساب مع قفل حصة متزامن. لا تُقبل SVG أو عناوين خارجية. الغلاف الخاص لا يُعرض لحساب غير مالكه أو أحد أعضاء الغرفة المصرّح لهم.

## الصوت المحلي

يدعم الخادم وضعين صريحين. `LIVEKIT_MODE=gateway` (الافتراضي) يحتاج `LIVEKIT_URL` لبوابة الإشارات و`LIVEKIT_INTERNAL_URL` لخادم SFU الخاص، مع عنوانين مختلفين وعزل إشارات SFU عن المشاركين. `LIVEKIT_MODE=cloud` يستخدم عنوان مشروع LiveKit Cloud مباشرةً، ويجب غياب `LIVEKIT_INTERNAL_URL`. يحتاج الوضعان `LIVEKIT_API_KEY` و`LIVEKIT_API_SECRET` على الخادم فقط. تفاصيل الوضع السحابي وإلغاء الرموز في [إعداد Cloud](cloud.md).

لا توضع المفاتيح في متغيرات `NEXT_PUBLIC_*`. الإعداد المحلي المؤقت في `/tmp/tahaddi-voice-local/session.env` بصلاحيات600؛ يُحمّل في عملية التطوير دون طباعته. خدمة الصوت الخاصة على7880، والبوابة على7890، وتطبيق Next المحلي على3000. شغّل البوابة بـ `node scripts/voice-signaling-gateway.mjs` بعد تحميل الإعداد وتعيين `VOICE_APP_ORIGIN=http://127.0.0.1:3000`. تفاصيل الخدمة والاختبار في [توثيق الصوت](audio-local.md).

رمز الانضمام صالح٦٠ ثانية ومقيّد بالغرفة والحساب ومصدر الميكروفون وإصدار جلسة الحساب. في وضع البوابة، يتحقق كل اتصال وإعادة اتصال عبر `/api/voice/admit`. في Cloud يُحفظ سجل إصدار داخلي ويُستخدم `RemoveParticipant` مع `revokeTokenTs` صريح عند تغيير الصلاحيات أو إزالة العضو، حتى إن لم يكن متصلًا. تتشارك أوامر الغرفة وإصدار الرموز وإلغاؤها قفل PostgreSQL واحدًا.

يجب توصيل Webhook LiveKit الموقّع إلى `/api/voice/webhook` لمراجعة المنضم حديثًا وتغييرات العضوية، مع مزامنة الصلاحيات داخل قفل PostgreSQL. لا نعِد بإلغاء دون أي نافذة سباق: قد يتغير الدور بعد رد القبول وقبل اكتمال الاتصال، ويصححه Webhook الموقّع. كما أن تسوية الحضور تعتمد على الطلبات حاليًا، وليست خدمة تنظيف مستقلة. غياب الإعداد يعرض حالة صريحة بدل نجاح وهمي.

الخدمة الخارجية تحتاج WSS/HTTPS وشهادة صحيحة ومسارات وسائط وTURN وموارد ملائمة. أضيفت أصول مشروع Cloud ونقاطه الإقليمية المحددة إلى سياسة Vercel العامة و`next.config.ts` من قائمة `config/voice-cloud-origins.json` دون wildcard عام. تسمح مستندات التطبيق بالميكروفون من الأصل نفسه، لأن سياسة المستند الأول تظل نافذة أثناء تنقل App Router بين الغرف والألعاب؛ يظل إذن المستخدم مطلوبًا. يُمنع الميكروفون صراحةً في مستند لعبة المزرعة المستقل المضمن، ويعمل الصوت من التطبيق الأب.

## التحقق والمراجعة

راجع [سجل القبول](acceptance.md) لأوامر الاختبارات ونتائجها وما لم يُختبر. تستعمل اختبارات HTTP قاعدة محلية منفصلة تبدأ باسم `voice_test` فقط، وتتحقق من المصادقة والسباقات والصلاحيات والدعوات والرفع. لا تستخدم إعداد Prisma الجذري للمهاجرات الاختبارية؛ ملف `scripts/voice-qa-prisma.config.ts` يمنع استبدال وجهة الاختبار بإعداد بيئة آخر.

نجاح اختبارات API أو الصوت المولد لا يثبت تجربة الميكروفون على جهازين فعليين أو سلامة العرض في المتصفح. لا تعتبر النسخة مقبولة بصريًا أو جاهزة للإنتاج قبل توفير لقطات المتصفح المطلوبة واختبار الجهازين والشبكتين. لا تعدّ الصور المولدة للأغلفة لقطات شاشة للتطبيق.
