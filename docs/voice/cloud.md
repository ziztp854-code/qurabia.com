# LiveKit Cloud للتجربة الأولى

مشروع المالك: `tahaddi-live-hombip0z.livekit.cloud`، مع خطة Build المجانية المختارة للتجربة. تُحفظ القيم في Vercel لمشروع `tahaddi-platform-realtime` ضمن Production: `LIVEKIT_MODE=cloud` و`LIVEKIT_URL`، مع `LIVEKIT_API_KEY` و`LIVEKIT_API_SECRET` كأسرار. يجب ألا يوجد `LIVEKIT_INTERNAL_URL` في هذا الوضع. لا تُحفظ المفاتيح في المستودع أو متغيرات المتصفح.

## الصلاحيات وإعادة الاتصال

يبقى تسجيل الدخول وعضوية الغرفة والمقعد مصدر الصلاحيات. يُسجل كل إصدار رمز في `VoiceRoom.state.mediaGrants` داخل المعاملة نفسها، دون هجرة جديدة، ولا يخرج السجل في الاستجابات العامة. يتشارك السجل وأوامر الغرفة قفل PostgreSQL لكل غرفة؛ تزيد كتابة السجل رقم المراجعة حتى تعيد الأوامر المتزامنة قراءة الحالة بدل استبداله بنسخة قديمة.

عند إزالة عضو، أو إغلاق الغرفة، أو تغيير حق النشر، أو تغيير إصدار جلسة الحساب/وقت الانضمام، تستدعي التسوية `RemoveParticipant` مع `revokeTokenTs` صريح. يغطي السجل الأعضاء غير المتصلين أيضًا. يُختار حد الإلغاء بعد نهاية الثانية الحالية بثانية، وتُرفض إعادة إصدار رمز قبل مروره بكود `MEDIA_RETRY`. يفصل تغيير صلاحية المايك اتصال Cloud؛ يعيد المستخدم الاتصال بزر الصوت بعد لحظات وبصلاحياته الجديدة. التنقل إلى الألعاب وحده لا يغير الصلاحيات أو الاتصال.

تسوية تغييرات الحساب والحضور ما زالت تعتمد على طلبات الغرفة أو Webhook الموقّع، وليست عامل تنظيف دوريًا. لا يوجد ضمان لإلغاء حساب خامل دون أي طلب جديد. بيانات أدوار العميل لا تمنح حق النشر. يظل مسار البوابة متاحًا للاستضافة الذاتية، ولا يمكن تفعيل Cloud على نطاق SFU عشوائي.

## فحص النشر

`scripts/voice-cloud-check.mjs` يعمل قبل بناء إنتاج Cloud ويتجاوز المعاينات. ينشئ غرفة اختبار باسم UUID، ويتحقق من اتصال الإشارات، ورمز التحديث الصادر من الخدمة، ورفض الرمزين الأصلي والمحدث بعد الإلغاء الصارم، وإلغاء رمز هوية غير متصلة، وإعادة الاتصال برمز مستمع جديد. يتحقق من نقاط الاكتشاف الإقليمية مقابل قائمة CSP المحددة. يحذف غرفة الاختبار الخاصة به، ويوقف النشر عند فشل أي فحص. لا يسجل الرموز أو الأسرار.

يشغّل فحص النشر أيضًا عميلين أصليين لنقل نغمتين مولّدتين والتحقق من PCM المفكوك في الاتجاهين، مع إزالة غرفة الاختبار بعد الانتهاء؛ راجع [دخول الأعضاء وفحص الصوت](entry-and-audio-check.md). هذه تجربة لمسار WebRTC بين عميلين على آلة واحدة، ولا تثبت صوت الميكروفون الفعلي بين جهازين وشبكتين أو استمرار الحديث أثناء اللعب. نجاح jsdom أو فحص النشر لا يثبت هذا القبول.

قائمة CSP تتضمن نطاق المشروع ونقاطه الإقليمية المنشورة في [دليل جدار الحماية الرسمي](https://docs.livekit.io/deploy/admin/firewall/). عند تغيير المشروع أو إضافة المزود منطقة جديدة تُحدّث القائمة وسياسة `vercel.json` معًا. للمقارنة، توثق LiveKit [إلغاء الرموز ونافذة الدقيقة الافتراضية](https://docs.livekit.io/frontends/reference/tokens-grants/)؛ لا يعتمد التنفيذ على النافذة الافتراضية.

للعودة إلى الإصدار السابق يمكن استخدام نشر Vercel السابق دون حذف جداول الغرف أو بيانات الحسابات. غياب وضع Cloud في إصدار سابق يبقي الصوت غير مهيأ، لأن الإعداد القديم يحتاج بوابة وSFU خاصين.
