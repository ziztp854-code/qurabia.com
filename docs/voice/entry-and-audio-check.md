# دخول الأعضاء وفحص الصوت

تظهر شارة ترحيب ذهبية بصورة الحساب واسمه عند دخول عضو أو عودته، اعتمادًا على لقطات عضوية الخادم المقبولة. عند فتح الغرفة لأول مرة يُرحّب بالمستخدم نفسه؛ لا تُعرض قائمة الموجودين كأنهم دخلوا للتو. تُحصر الشارات المعلقة بثلاث، وتختفي تلقائيًا مع زر إخفاء. لا تعلن ضربات الحضور أو تغيير الاسم دخولًا جديدًا. تتوقف الحركة مع prefers-reduced-motion، ولا تنتزع الشارة تركيز لوحة المفاتيح أو تظهر فوق حوارات الغرفة.

داخل شريط الصوت توجد «فحص الصوت»: اختبار ميكروفون بمؤشر حي لمدة عشر ثوانٍ، ونغمة سماعة مع تأكيد يدوي للسماع. لا يُفتح جهاز أو تُشغّل نغمة قبل فعل المستخدم. أثناء البث يُقاس المسار المنشور نفسه دون إيقافه؛ أثناء الكتم أو الاستماع يُفتح مسار محلي مستقل لا يُنشر. لا يُستخدم MediaRecorder ولا تُحفظ عينات الصوت. يغلق الفحص موارده عند الإيقاف، أو إغلاق اللوحة، أو تغيير الجهاز/حالة المايك، أو إخفاء الصفحة، أو إزالة المكون. يُوقف أيضًا المسار الذي يصل بعد إغلاق نافذة إذن معلقة. قد يستخدم اختبار السماعة خرج النظام الافتراضي إذا لم يدعم AudioContext توجيه الخرج؛ يظهر ذلك صراحة.

## فحص نقل الصوت على المزود

أضيف `voice-cloud-audio-check.mjs` إلى فحص بناء الإنتاج. ينشئ غرفة اختبار معزولة باسم UUID خارج بادئة غرف التطبيق، ثم يصل عميلان أصليان بالخدمة وينشر كل منهما نغمة مختلفة 440/660Hz. يقيس الفحص عينات PCM المفكوكة في الاتجاهين ويشترط نصف ثانية على الأقل وطاقة مسموعة ونسبة طاقة النغمة المتوقعة إلى النغمة الأخرى أكبر من عشرة. لا يعتبر اتصال الإشارات أو عينات الصمت نجاحًا. يخفي العملية الأصلية عن سجلات البناء، ويعرض قياسات رقمية دون مفاتيح أو رموز. العملية محدودة بـ45 ثانية، وتحذف العملية الأم غرفة الاختبار حتى عند فشل العميل.

هذه تجربة صوت مولّد بين عميلين على آلة بناء واحدة، وليست ميكروفون شخصين أو شبكتين أو اختبار متصفح. يلزم اختبار الجهازين للسماع الفعلي واستمرار الحديث أثناء اللعب. لا تعني نتيجة المؤشر المحلي وصول الصوت إلى الآخرين.

## مراجعة الاعتماد

اختير SDK LiveKit الرسمي `@livekit/rtc-node@1.1.0`، مثبت الإصدار في devDependencies وملف القفل، من [livekit/node-sdks](https://github.com/livekit/node-sdks/tree/main/packages/livekit-rtc)، برخصة Apache-2.0. روجعت README وواجهات تدفق الصوت والإطار والإغلاق وبيانات npm وتبعيات FFI. يدعم Node>=18، وحُمّل محليًا على Node24.19. يعتمد FFI0.12.73 بملف Linux x64 نحو25.6MB؛ لا توجد install/postinstall scripts في الحزمتين المراجعتين. يوفر نقل WebRTC أصليًا غير متاح في server SDK المستخدم للرموز والإدارة. لا يُستورد في المتصفح أو مسارات تشغيل التطبيق؛ يستخدمه فحص البناء فقط. يستهلك عميلان دقائق قليلة من حصة Cloud، دون تغيير الخطة أو إنشاء اشتراك آخر. أُبقيت إصدارات تبعيات المشروع السابقة دون ترقيات غير مرتبطة.

## التحقق والقبول

نجحت90 حالة في11 ملفًا للصوت والمكونات، ومنها اختبارات الدخول، الصمت/الإشارة، الإذن المرفوض، المسار المتأخر، حفظ مايك البث، تبديل الجهاز، وإقرار سماع النغمة. نجح بناء web وESLint للنطاق المعدل، واختبارات Goertzel والبوابة وحارس الهجرة. فحص SDK المحلي توقف عند حظر proxy403؛ لم يُتجاوز القيد. تُراجع نتائج نقل Cloud الفعلية في سجل نشر الإنتاج.

مراجعة Art Director / Visual QA: مراجعة ذاتية للشفرة والـRTL والتوكنات؛ الهوية من Cairo/ذهب تحدي ومكونات Avatar الحالية، وأهداف التفاعل44px. لا تتوفر أداة متصفح متصلة في هذه الجلسة، لذلك لا توجد صور قبل/بعد أو قياسات320px/200% أو اعتماد بصري نهائي. الحالة البصرية **unverified**، دون درجة مفترضة. يلزم التحقق من عدم حجب الشارة للمحتوى ومن الالتفاف والتركيز على سطح مكتب وجوال فعليين. هذه الحدود لا تغيّر صلاحيات الغرفة أو قواعد الألعاب.
