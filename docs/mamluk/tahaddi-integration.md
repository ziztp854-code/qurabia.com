# حرب المماليك: التوسعة داخل تحدي

الحالة: **اختار المستخدم توسعة تحدي الممالك الموجودة**. الحساب والمحرك وPostgreSQL وعامل realtime هي أساس التنفيذ. لا تحويل إلى Revana أو محول PHP أو مشاركة جلسات بين محركين.

المرجع: [01829449dffc16603de3fa5998bf475a961607ce](https://github.com/ziztp854-code/qurabia.com/commit/01829449dffc16603de3fa5998bf475a961607ce)، محليًا في _release_kingdoms_latest/. [خطة المراحل](../../MAMLUK_MIGRATION_PLAN.md).

## ما يعاد استخدامه

المواضع التالية داخل المرجع المثبت:

| المسؤولية | الموضع | عقد التوسعة |
|---|---|---|
| Game Core | apps/web/src/lib/kingdoms/engine.ts وsimulation.ts | إنتاج وتكلفة وتدريب ومسير ونتائج؛ توسعة القادة والحصار دون محرك ثان |
| Game Data | types.ts وconfig.ts | مفاتيح مستقرة وبيانات مناطق ومبان ووحدات بإصدار وتحقق وتوافق |
| Authentication Adapter | identity.ts وخدمات auth الحالية | جلسة تحدي إلى هوية لاعب صالحة؛ لا حساب أو كلمة مرور جديدة |
| API | apps/web/src/app/api/kingdoms/route.ts وcommands.ts وhttp.ts | صلاحيات ومدخلات ومعدل وorigin وإيصال؛ لا نتيجة قتال من العميل |
| Persistence | repository.ts وPrisma | وقت قاعدة البيانات وقفل ومعاملة وحالة ومراجعة وموعد وإيصال معًا |
| UI | apps/web/src/components/kingdoms | إسقاط مأذون وأفعال وعد تنازلي؛ لا اقتصاد حاسم داخل العرض |
| Worker | apps/realtime/src/kingdoms/kingdoms.worker.ts | معالجة المواعيد وإشعار المراجعة دون حالة لعبة موازية |

## الحساب مدمج بالفعل

[identity.ts](https://github.com/ziztp854-code/qurabia.com/blob/01829449dffc16603de3fa5998bf475a961607ce/apps/web/src/lib/kingdoms/identity.ts) يقرأ جلسة تحدي ثم حالة المستخدم وtokenVersion وصلاحية المدير عند الحاجة. [repository.ts](https://github.com/ziztp854-code/qurabia.com/blob/01829449dffc16603de3fa5998bf475a961607ce/apps/web/src/lib/kingdoms/repository.ts) يعيد فحص المستخدم داخل المعاملة بعد انتظار القفل، فلا ينفذ أمر جلسة أُبطلت أثناء الانتظار.

يبقى معرف اللاعب الثابت وفحص ملكية المدينة والجيش لكل أمر. فصل محول الهوية حدود قابلة للاختبار، وليس مشروع SSO جديدًا. لا مطابقة بالاسم أو نسخ كلمات مرور أو جداول مستخدمين أخرى. الحساب والإبطال وصلاحيات الإدارة تستمر بالعقود الحالية.

## الخادم والوقت مصدر الحقيقة

المستودع يقفل KingdomWorld باستخدام FOR UPDATE، يستخدم وقت PostgreSQL، ويمنع تكرار الأمر بإيصال العالم واللاعب والمفتاح وبصمة المحتوى. الحفظ يجمع الحالة والمراجعة وnextEventAt. المحاكاة تعمل على نسخة الحالة، والإسقاط يرشح بحسب اللاعب.

[العامل](https://github.com/ziztp854-code/qurabia.com/blob/01829449dffc16603de3fa5998bf475a961607ce/apps/realtime/src/kingdoms/kingdoms.worker.ts) يطلب ticks بمسار داخلي محمي ويعلن مراجعة العالم. المواعيد تبقى بعد إغلاق المتصفح أو إعادة تشغيل العامل؛ WebSocket ليس سجل أحداث أو ضمان وصول. العميل يستعيد حالة مأذونة أحدث.

مواعيد القادة والتعافي والحصار المستقبلية تدخل nextDeadline والمعالجة الحتمية نفسها. لا عامل منافس يصرف مكافأة أو يحسم حصارًا خارج المعاملة. لا تغيير وقت وصول جيش بسبب إعادة تصميم أو إعدادات افتراضية جديدة.

## الفجوات التي تحتاج تنفيذًا أصليًا

- المباني: 11 مفتاحًا حاليًا؛ المباني التاريخية الإضافية ووظائفها ومتطلباتها غير موجودة.
- الوحدات: أربعة أنواع؛ المشاة والرماة والحصار وsiegePower/unitType توسعة صريحة، وليست أسماء بديلة فقط.
- القائد: غير موجود؛ حجز وحالة وخبرة وتقرير ومصير عند هلاك الجيش. returnMovement الحالية لا تعيد حملة بلا ناجين.
- الحصار: غير موجود؛ القتال فوري عند الوصول ولا يكسر المباني. نضيف مراحل وإمداد وضرر وانسحاب فوق الحساب القائم.
- المناطق: لا بيانات للقاهرة ودمشق وغيرها؛ التضاريس الحالية رسم دون أثر سفر.
- الرؤية: لا قوات عدو في خريطة العالم، والاستطلاع لقطة فقط. النطاق والأبراج والصلاحية والمشاركة امتدادات مطلوبة.
- السلطنة: العضوية والأدوار والتعزيز موجودة؛ خزينة ورسائل وأدوار سلطنة وسجل حرب طويل غير موجودة.
- الدبلوماسية: peace/ally/war فقط؛ عدم اعتداء وعداء وسجل تغيير يحتاجان تعريفًا واختبارًا.
- التقدم: مستوى مبنى ونقاط مملكة، لا خبرة بطل. المهام والفعاليات نقاط وصل لتقدم موثوق لاحقًا.
- السوق: فوري وذري؛ ليس قافلة بوقت وصول حتى تنفذ القاعدة.

## حفظ اللاعبين والعوالم

الأفضل قواعد مملوكية بعالم جديد بإصدار بيانات مستقل داخل المحرك نفسه؛ يبقى /games/kingdoms والعالم الحالي وموارد أصحابه ومواعيده. لا يمحو إصدار جديد نتائج موسم أو يعيد ضبط لاعب تلقائيًا.

تحويل عالم قائم اختياري يحتاج عملية منفصلة بتقرير وتسوية وتجربة معزولة، تحفظ الموارد والأعداد والملكية والمواقع والحملات ومواعيد البناء والتدريب. لا تغيير تفسير وحدة قديمة أو معركة منتظرة بصمت. الحقول الجديدة تُقرأ بتوافق قبل حفظ إصدار أحدث.

العالم صف JSON كامل، فتسلسَل الكتابات وتزداد كلفتها مع الحجم. نقيس الأقفال والمعاملة والحجم وتأخر الأحداث قبل توسيع العالم؛ استخراج خدمة أو جداول ليس جزءًا تلقائيًا من تغيير الهوية.

## قبول المرحلة الأولى والتوسعة

نتحقق من المرجع دون تعديل موازنته أو إنتاجه: اختبارات المحرك وAPI وlint/typecheck/build وHTTP محلي ورفض القراءة والكتابة والإدارة للمجهول. الدخول وإنشاء عالم وبناء وتدريب وتزامن المعاملات يحتاج PostgreSQL اختبار مستقلة؛ غيابها يسجل تجاوزًا لا نجاحًا.
