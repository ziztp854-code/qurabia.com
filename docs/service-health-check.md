# فحص توفر الموقع وخدمة اللعب المباشر

الفحص للقراءة فقط، ويتطلب تحديد عنوانين صراحةً لكل تشغيل:

```sh
TAHADDI_WEB_HEALTH_URL='http://127.0.0.1:3000/' \
TAHADDI_REALTIME_HEALTH_URL='http://127.0.0.1:3001/realtime/health' \
  node scripts/check-service-health.mjs
```

يقيس الفحص زمن الاستجابة ويعتبر ما يزيد على ٥٠٠٠ ملّي ثانية بطيئًا؛ يمكن ضبط الحد باستخدام `TAHADDI_HEALTH_MAX_MS` بين ٢٥٠ و٨٠٠٠. يرفض الفحص التحويلات ويتحقق من استجابة HTML للموقع وحقول `service` و`status` لخدمة اللعب المباشر. يعيد رمز خروج 0 عند نجاح الفحصين، و1 عند فشل أحدهما، و2 عند غياب الإعدادات؛ يمكن ربطه بنظام مراقبة موجود. اختبر سلوكه محليًا بواسطة `node --test scripts/check-service-health.test.mjs`.

هذا فحص توفر أساسي، ولا يثبت اتصال قاعدة البيانات أو Redis أو نجاح انضمام اللاعبين، ولا ينشئ تنبيهات أو مراقبة دورية بحد ذاته. استخدم عنوان نقطة الخدمة الفعلية، وتأكد من اختبار تدفق غرفة مباشر منفصلًا ببيانات اختبار مناسبة.

يوجد سير GitHub Actions في `.github/workflows/service-health.yml` يعمل كل ٣٠ دقيقة أو يدويًا بعد نشره على الفرع الافتراضي. يلزم ضبط سري المستودع `TAHADDI_WEB_HEALTH_URL` و`TAHADDI_REALTIME_HEALTH_URL`؛ عند غيابهما يسجل السير تنبيه إعداد ولا يجري أي اتصال. يحدد GitHub إشعارات فشل التشغيل وفق إعدادات المستودع والمستخدم؛ لا ينشئ السير قناة تنبيه مستقلة.
