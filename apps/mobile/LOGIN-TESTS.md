# اختبار إصلاح تسجيل الدخول في Android 0.2.1

فرع العمل: `fix/android-auth-login`، مبني على عميل PR #74 داخل `apps/mobile`.
لا يغيّر هذا الإصلاح مصادقة الموقع أو API أو قاعدة بيانات الإنتاج.

## التغيير

- تفسير غلاف NextAuth `{url}` عند HTTP 401، دون إظهار الرابط أو تفاصيل المزوّد الخام.
- تمييز رفض CSRF ذي HTTP 200، ورفض تسجيل الدخول، ومشكلة الخادم أو الشبكة، وغياب الجلسة بعد قبول callback.
- الاحتفاظ بالنموذج أثناء الطلب؛ التحميل المحلي ومنع الطلب المتكرر يبقيان فعالين.
- الانتقال للحساب الموثّق يحدث بعد فحص جلسة الخادم ووجود كوكي الجلسة فقط.
- حفظ HTTPS وOrigin ومخزن Cookies الخاص ومنع التحويلات كما كانت.

رمز `CredentialsSignin` لا يثبت أن كلمة المرور خاطئة: الخادم يستخدمه أيضًا لسياسات الحساب وحد المحاولات.
لذلك تصف الرسالة العربية رفض البيانات ولا تجزم بسبب لم يقدمه الخادم.

## Workflow والأدلة

`.github/workflows/android-auth-login.yml` يعمل على الفرع وعلى PR إلى
`codex/android-native-v2`. يبدأ بفحص أنواع العميل واختبارات الانحدار وحماية أدوات QA.
يبني بعدها APK مستقلًا بلا Metro، ويفحص توقيعه وحزمته ويشغّل الاختبار العام على API 36.

يُحفظ APK الموزّع في `android-delivery/app-debug.apk` قبل إعداد أي شهادة اختبار،
ويُرفع باسم `tahaddi-debug-RUN_ID-ATTEMPT`. حجمه وبصمته وإصداره في تقارير البناء.
هذا Debug تجريبي؛ لا توجد مفاتيح إنتاج جديدة أو نشر متجر.

أرشيف `android-reports-RUN_ID-ATTEMPT` يتضمن:

- سجلات الأنواع والتبعيات وGradle والتوقيع.
- `login/login-protocol.json`: مقارنة خطأ النسخة القديمة بالتصنيف الجديد عبر NextAuth الحقيقي،
  ودخول صحيح واستعادة مخزن الجلسة وخروج. هذا الاختبار يستخدم نقل Node ولا يثبت Android وحده.
- `login/login-result.json`: نتائج إدخال Android الفعلي، رفض محاولة خاطئة، الدخول الصحيح،
  إنهاء العملية وإعادة فتحها مع SecureStore، ثم الخروج وإعادة الفتح.
- المصدر المتتبّع من نفس الالتزام داخل `tahaddi-android-source.tar.gz`.

وجود APK لا يعني نجاح الدخول؛ المرجع هو نتيجة خطوة التكامل وملفات النتائج الفعلية.

## الحساب المعزول وHTTPS

يعمل PostgreSQL مؤقت باسم `mobile_login_test` على loopback داخل runner فقط.
ينشئ `scripts/login-fixture.ts` مستخدمًا عشوائيًا ACTIVE بكلمة مرور مولّدة تحتوي
رموز ترميز النموذج، ثم يحذفه بالـID عند إغلاق fixture.
لا يستخدم الاختبار حسابات المستخدمين أو بيئة الإنتاج.

الخادم هو Next وتطبيق NextAuth الفعليان، خلف HTTPS على `localhost:3443`.
يستخدم الاختبار `NODE_ENV=development VITEST=1` لحفظ أصل HTTPS في إعداد URL المحلي
الموجود، وتبقى سياسة تحديد المحاولات غير الإنتاجية معلنة. يختبر CSRF وتجزئة كلمة المرور
وJWT والجلسة وقاعدة البيانات الحقيقية، ولا يثبت سياسة limiter الإنتاجية.

تُنشأ CA محلية مؤقتة وAPK اختبار منفصل يثق بها لنطاق localhost فقط.
يوجّه `adb reverse tcp:3443 tcp:3443` هذا الخادم إلى المحاكي؛ لا يوجد Metro.
لا يُرفع APK الاختبار أو مفتاح الشهادة، ولا تتغير ثقة TLS في APK الموزّع.
يُعاد فحص بصمة APK الموزّع بعد اختبار النسخة المنفصلة.

## الخصوصية وحدود النتيجة

ملف الحساب الخاص وصلاحياته 0600، والمفاتيح والسجل الخام للخادم خارج مجلد artifacts.
لا تُرفع كلمات مرور أو Cookies أو Tokens أو صور/XML لشاشة تحمل بيانات الحساب.
تقارير الدخول تحتوي مراحل ورموزًا آمنة وعدادات والتحقق من مطابقة هوية الحساب المعزول فقط.

اختبار الهاتف الذي أبلغ عنه المستخدم ليس مماثلًا لمحاكي localhost.
نجاح الحساب المعزول لا يثبت إصلاح كل أسباب رفض الحسابات في نشر الإنتاج أو على جميع الأجهزة.
تُوثّق النجاحات والإخفاقات المنفذة في PR؛ لا يُستنتج نجاح دخول من GET عام أو من نجاح Gradle.
