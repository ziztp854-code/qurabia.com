# بناء Android لتحدّي

## نطاق التطبيق الحالي

التطبيق الموجود في apps/mobile هو شاشة React Native لإدخال رمز مسابقة وفتح
https://qurabia.com/join/{code} في المتصفح الخارجي. لا توجد داخله بعد جلسة
مصادقة أو غرفة صوتية أو دردشة أو Socket.IO. بناء APK لهذه الشريحة لا يحقق
وظائف المنصة الكاملة، ولا يثبت اتصال Android بخدمات الصوت.

المعرّف الحالي: com.qurabia.tahaddi. إصدار المصدر: 0.1.0.

## بناء Debug دون بيئة محلية أو حساب EAS

Workflow: .github/workflows/android-debug.yml

يبدأ عند دفع تغييرات الجوال إلى codex/android-apk-ci أو في طلب دمج يمس الملفات
المحددة. يمكن تشغيل workflow_dispatch بعد وجود Workflow على الفرع الافتراضي.
لا حاجة إلى دمج الفرع لتشغيل حدث push. لا يعدّل Workflow الفرع الرئيسي ولا ينشر
على متجر أو استضافة.

بيئة البناء: Ubuntu 24.04، Node 24.14.0، pnpm 11.26.0، Temurin Java 17.
تُستخرج إصدارات compileSdk وBuild Tools وNDK من حزمة React Native المثبتة
بالـlock، وتُثبت عبر sdkmanager. Gradle Wrapper يأتي من قالب Expo المطابق للحزمة.

قبل Gradle:

1. التحقق من وجود الإصدارات المعلنة في npm.
2. تثبيت mobile واعتماديات workspace الخاصة به بـ frozen-lockfile وignore-scripts؛
   لا تُشغّل دورة تثبيت خادم Prisma أو أدوات الويب.
3. بناء domain، وفحص TypeScript، وتشغيل اختبارات join-flow ومساعدات البناء.
4. تسجيل خريطة Expo المثبت نفسه وتشغيل EXPO_OFFLINE=1 expo install --check؛ لا يوجد إصلاح
   تلقائي للإصدارات أو تجاهل لفشل التوافق. هذا فحص حتمي لخريطة SDK المحلية،
   دون توصيات API الأحدث. يبقى minimumReleaseAge مفعّلًا دون استثناء، ولا يُضبط
   Offline لباقي خطوات البناء. حُفظ إصدار Expo الأصلي 57.0.23 مع تصحيح حزم native.
5. اختبار Metro والأصول عبر expo export ثم expo prebuild --platform android --no-install.

يعدّل prepare-android-debug.cjs الملفات الأصلية المولدة فقط، مع التوقف إذا
اختلف القالب المتوقع: يضمّن JS والأصول في debug ويعطّل Metro في React host.
لا يعدّل إعداد توقيع release. لا تشغله مرتين على نفس مشروع Android المولّد؛
لإعادة المحاولة ولّد مشروعًا جديدًا بعد حفظ أي عمل محلي.

الناتج المتوقع بعد نجاح Gradle:

    apps/mobile/android/app/build/outputs/apk/debug/app-debug.apk

يُفحص وجود JS داخل APK، ومعرّف الحزمة، وكونه debuggable، وصحة التوقيع.
يُرفع ملف APK فقط إلى artifact باسم tahaddi-debug-RUN_ID-RUN_ATTEMPT
لمدة 14 يومًا. يظهر رابط التنزيل في ملخص التشغيل. تُرفع أدلة البناء والحجم
وSHA256 والأذونات والسجلات في android-reports-RUN_ID-RUN_ATTEMPT، حتى عند الفشل.

بعد البناء، يثبت الاختبار APK على محاكي Android 36 x86_64 ويفتح الشاشة دون
Metro، ويتحقق من ظهور حقل الرمز وزر الانضمام، ويحفظ لقطة وlogcat. قد ينجح
البناء ورفع APK ثم يفشل المحاكي؛ تُقرأ نتيجة كل خطوة ولا يُعد ذلك نجاح تشغيل.

لتثبيت نسخة الاختبار بعد فك ضغط artifact:

    adb install -r app-debug.apk

أو انقل APK للهاتف واسمح بالتثبيت من المصدر المستخدم. مفتاح debug تجريبي
وقد يتغير بين تشغيلات CI؛ عند اختلاف الشهادة يلزم إزالة النسخة القديمة،
مما يمسح بياناتها. لا تستخدم هذه الشهادة لتحديث تطبيق إنتاج منشور.

## Release APK وGoogle Play AAB

الملف eas.json يضيف ملفي بناء release-apk وrelease-aab. كلاهما يستخدم
credentialsSource: local عمدًا. لا ينشئ هذا المسار مفتاح إنتاج بديلًا، ولا
يشغّله Debug Workflow. الربط بمشروع EAS وversionCode البعيد والتوقيع المعتمد
متطلبات يجب استكمالها قبل البناء.

بعد تجهيز المفتاح المعتمد خارج Git، اكتب apps/mobile/credentials.json محليًا
بصيغة EAS Android keystore الرسمية، مع مسار keystore وكلمة مروره والـalias
وكلمة مرور المفتاح. الملف والمفاتيح مستثناة من Git. لا ترسلها في الدردشة،
ولا ترفعها ضمن artifacts، ولا تسجل قيمها.

نفّذ بحساب EAS المعتمد وبعد اختيار المشروع الصحيح:

    eas build --platform android --profile release-apk --non-interactive
    eas build --platform android --profile release-aab --non-interactive

استخدم إصدار eas-cli معتمدًا ومثبتًا عند تشغيل الإصدار الفعلي. هذه أوامر بناء
فقط؛ لا تنفّذ eas submit ضمن هذه المهمة. افحص شهادة الناتج وقارن SHA256
بالبصمة المعتمدة، وتحقق من versionCode وtarget SDK والأذونات قبل التوزيع.
قالب Expo قد يربط assembleRelease المحلي بمفتاح debug؛ لا تستخدم نجاح هذا
الأمر وحده بوصفه إثبات توقيع إنتاج.

لتحديثات لاحقة: عدّل expo.version في app.json، وثبت التبعيات والـlock
المتوافقين، وشغّل الاختبارات والبناء والمحاكي، ثم اختبارات جهاز فعلي. حافظ
على Application ID وشهادة التوقيع المعتمدين، وزد versionCode وفق مشروع
EAS البعيد. لا توجد عملية نشر أو رفع متجر تلقائية هنا.

## حالة الاختبارات والتكامل

عند إعداد هذا المسار لم تتوفر بيئة أوامر محلية؛ حالة الخدمة pending/offline.
تظل نتيجة TypeScript والتثبيت والبناء والمحاكي معتمدة على نتائج Actions
الفعلية، ولا يجوز وصفها بالنجاح قبل تشغيلها.

اختبارات join-flow الحالية تختبر تطبيع الرمز وبناء الرابط فقط. اختبار المحاكي
الجديد يثبت تشغيل شاشة التطبيق، ولا يسجل دخولًا أو يرسل رسائل إلى الإنتاج.

فحص المصدر أثبت ما يلي، دون اختبار اتصال حي:

- الويب يستخدم NextAuth وCookies؛ نقاط صوت الكتابة تتحقق من Origin.
  لا تنتقل جلسة المتصفح تلقائيًا إلى native fetch.
- /voice يستخدم LiveKit. دردشته تحفظ الرسائل عبر HTTP مع LiveKit data
  للتسريع؛ Socket.IO يخدم مسارات الألعاب الأخرى.
- استمرار الغرفة يحتاج تحديث حضور؛ العضوية تنتهي بعد 90 ثانية دون تحديث.
- للدردشة حد 40 كتابة/60 ثانية مع حد إضافي بين رسائل المستخدم؛ اختبار
  100 رسالة يجب أن يحترمه ويقارن IDs وإقرارات الخادم.
- توجد اختبارات ويب/SFU ومحاكاة؛ لا تعادل اختبار Android فعليًا.

لم تُختبر في هذه الدفعة: مصادقة أصلية، دخول غرفة، الميكروفون، Bluetooth،
100 رسالة فعلية، تبديل الشبكة، قفل الشاشة، المكالمات، جلسة طويلة،
RAM/CPU/البطارية أو جهاز فعلي. تحتاج هذه الوظائف تنفيذ عميل Android أولًا
وبيئة اختبار معزولة، دون تغيير API أو بيانات الإنتاج لتجاوز العقبات.
