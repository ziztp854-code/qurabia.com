# Hero rules version 1

This is an independent Alfazaa implementation. The recovered client plays server combat logs; the original server damage, RNG, matchmaking and reward authorization were not recovered. NPC training opponents are never presented as human players.

## Source-backed values

The reproducible importer is `work/import_alfazaa_hero_gameplay.py` in the conversation workspace. It reads the extracted CSV tables and the original Arabic hero/art index. It imports 57 heroes, fragment acquisition costs, base/growth/star attributes, star costs, current-level XP requirements, born skill tiers and recommended skills, 36 equipment recipes, equipment enhancement costs, 32 formation levels, 1800 fortification rows, 165 campaign stages, 240 expedition stages, 1007 world monsters, 6 ruins, 120 tower configurations, and 12 mine configurations. The starter is the lowest-rarity, lowest-ID hero, William 62003, once per fresh save. The remaining heroes require fragments.

XP uses the current-level row consistently because recovered client previews use conflicting row indices. Quality4 level1 requires350XP. Skill unlock levels are0/20/40/60/100. XP books and skill XP books use their extracted values. Forgetting returns the actual skill book and whole small books representing60percent of invested skill XP. Two commanders and nine troop cells are supported. Duplicate recipe material entries are aggregated before checking balances. Equipment swaps preserve instance identity and enhancement level. First-clear awards and final expedition chapter awards are issued once through completion ledgers.

## Explicit independent adaptations

- Source amounts above1e9 are compressed to `floor(1e9*(1+log10(raw/1e9)))`, preserving source IDs, levels and probabilities. Source CSVs remain unchanged. Runtime combat values are integer-clamped to1e12.
- Crafting requires castle level `max(1,(quality-1)*2-1)` in place of the original EquipmentCollege tree. Enhancement deterministically gains one level for the extracted tier cost; source random enhancement XP is not reproduced.
- Commander attack adds `sum(attack)/100` to troop attack multiplier; commander defense adds `sum(defense)/100` to troop defense; command adds `sum(command)/100` to troop HP multiplier. Each learned skill level adds0.5percent attack. Source learned-skill subtype effects are not individually simulated.
- Formation levels add2percent per level to attack/defense/HP/speed for types1/2/3/4. Selected-position fortification adds1percent HP per level. These are effective independent bonuses, not recovered server coefficients.
- Enemy lineups use extracted monster armies. Missing wall/special/ruin lineups use one10001 troop stack of `1+floor(stage/2)`; this is disclosed fallback scaling. Count multiplies attack and HP. Original monster heroes, extra server attributes and structures are not fully simulated.
- Combat resolves synchronously from trusted state and command context using a seeded LCG, speed ordering and40round cap. Seed uses trusted time, battle counter and stage ID, never a client-provided seed/outcome. Damage is `max(1,floor(attack*(0.95+random*0.1)-defense*0.35))`. Surviving defenders win a time-out. The report is versioned, stores final units and at most120events, and explicitly flags log truncation.
- Born effects are adapted from descriptions into strike/heal/shield/poison/stun/weaken/buff. The first born-skill metadata supplies activation chance, target count, coefficient and round cadence. Higher born tiers change the skill ID and hero progression but do not claim full server-tier effect fidelity. Strike uses source Attr_percent with0.25minimum multiplier; healing is12percent HP, shield15percent, poison5percent HP for2turns, stun1turn, weaken20percent attack for2turns, buff15percent for2turns. Zero-chance source passives are not treated as active procs.
- Stamina cap100, regeneration1point/5minutes, campaign cost3 and other modes5. Rest costs500gold400001 for10stamina, max3/Riyadhday. Defeated city troops emit exact-cell wounded events for the shared healing system, avoiding permanent army loss.
- Campaign/expedition and NPC training stage progression is sequential with replays. Replays give no first-clear loot. Source monster castle/player requirements apply. Ruin random drops use the first extracted reward-pool entry as a fixed first-clear training reward. Tower rewards and20-stage rescue/arena/trial/dungeon/battlefield/war scenarios are independent20XP per stage-number training rewards. Mine fixed rewards are first-clear rewards; this does not emulate server map ownership or recurring extraction.

## Verification boundary

Public command tests exercise known source literals, immutable rejection, acquisition/progression, gear swapping, formation gates, reward-once and chapter reward behavior, defeat/wounded events, time regeneration, real2026 timestamp roundtrips, and rejection of forged outcomes/seeds. These prove the independent module's behavior, not equivalence to the unavailable original server. Root integration owns authenticated persistence, city troop removal/healing, API concurrency and browser verification.
