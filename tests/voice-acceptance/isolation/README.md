# Local signaling isolation fixture

Run `python tests/voice-acceptance/isolation/test_isolation.py` with Docker Desktop running. The default local images are LiveKit `89ca9ce0791e`, Playwright with Node `bc6ab0d6d44f`, and `python:3.12-slim` image `aa943ce41142`; set `VOICE_ISOLATION_SFU_IMAGE`, `VOICE_ISOLATION_NODE_IMAGE`, and `VOICE_ISOLATION_PROBE_IMAGE` if using different locally available images. Images are never pulled. The test creates unique containers and networks, generates a temporary test-only key pair, and removes only those named resources and its temporary environment file. It makes no changes to production settings.

The gateway shares the SFU network namespace so that its existing local-only HTTP upstream policy is respected. Only gateway port 7890 is published, and only on host loopback; SFU 7880 is not published. A probe on the trusted bridge must reach the SFU by IP, an authenticated test administrator on that bridge must successfully list rooms, whereas a probe on an independent bridge must not connect. A host client verifies a successful actual WebSocket upgrade via the project gateway to LiveKit and a rejected admission. The admission function is a **test double** which supplies a locally signed test token. It does not exercise the application database, real user membership, refresh tokens, disconnects, or retry worker.

This is a local Docker networking test, not production isolation evidence. Network access and firewall rules of the eventual deployment must be tested separately from outside its trust boundary, including direct signaling and any alternate IP addresses. This test does not isolate, exercise, or validate WebRTC media/ICE/UDP/TCP ports, end-to-end audio, or browser/device reconnection. The implementation must provide and verify the required media connectivity without making signaling reachable directly. The fixture tests no external hosting provider or production credentials.
